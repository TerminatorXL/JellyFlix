# JellyFlix add-on

*Developer documentation. If you just want to install the plugins, read the
[README](../README.md) ([po polsku](../README.pl.md)) instead.*

A standalone JavaScript add-on for the **Jellyfin 12.x web client**. No theme, no server-side CSS, no
dependencies — just a Jellyfin you are logged into.

Two of the five modules are features you can see:

* **pauseInfo** — pause playback and the film or series logo, the episode title and the synopsis fade
  in over the frame.
* **episodePicker** — while a series is playing, a button in the player opens a drawer with the
  current season's episodes and a season selector; picking one starts it.

Both are self-contained and ship their own stylesheets. The other three put information into the DOM
for a stylesheet of your own to render, and are inert without one: **rowTags** (name the home rows so
CSS can address them), **scrollVar** (scroll position as a CSS variable) and **cardMeta**
(synopsis/genres/runtime on cards, off by default).

There is no custom-JS hook anywhere in jellyfin-web 12.1, so the bundle has to be delivered from
outside the app. The repository carries a **Jellyfin plugin** that does exactly that, so the add-on
installs from the plugin catalogue like any other — see [Installing](#installing).

```
addons/          the add-on sources — the shared JavaScript framework (below)
plugins/         one directory per Jellyfin plugin (C#, net10.0)
  pause-info-card/   the pause card, plus the three CSS hooks
  episode-picker/    the in-player episode and season picker
dist/            jellyflix-addon.user.js (everything, for a userscript), bundles/<slug>.js (what
                 each plugin embeds) and plugin/<slug>_<version>.zip for the catalogue
manifest.json    the plugin repository file, one entry per plugin, regenerated by the build
tools/           build, deploy and check scripts
```

```
addons/
  header.js            the userscript metadata block (@name, @match, …) + the install notes
  core/                infrastructure; no module may be required to understand another module
    00-namespace.js    the JFX object, also exposed as window.JellyFlixAddon
    10-util.js         logging, DOM building, slugs, debounce, CSS injection, the string table
    20-api.js          read-only bridge to the Jellyfin REST API (window.ApiClient's four getters)
    30-player.js       playback bus: attach/detach/play/pause/seeking/ended/item, item resolution
    40-registry.js     JFX.register / JFX.setConfig / JFX.start, config merge, module lifecycle
    50-home.js         "which .homeSectionsContainer is the visible one" (rowTags + cardMeta)
  mods/                one file per feature; a module never reaches into another module
    10-row-tags.js     data-jfx-row="<slug>" on every home row
    20-scroll-var.js   --jflix-scroll: 0…1 on <html>
    40-card-meta.js    data-jfx-overview/-genres/-runtime on cards, off by default
    50-pause-info.js   the pause info card — logo + synopsis over a paused frame
    50-pause-info.css  its baseline stylesheet, inlined into the bundle at build time
    60-episode-picker.js   the in-player episode and season picker
    60-episode-picker.css
  90-boot.js           calls JFX.start() once every module has registered
```

`npm run build` concatenates all of it into **`dist/jellyflix-addon.user.js`** — one file, one IIFE,
no imports, ES5 only, because this has to run on TV browsers down to Chromium 68 / webOS 5 where
`let`, arrow functions and template literals are a coin flip. `npm run build:bundles` also writes one
bundle per plugin (`--bundle <name> --mods <files> --out <path>`), each carrying the core plus only
the modules that plugin owns.

### Two plugins, one framework

Every bundle carries the same core, so installing two plugins would normally mean the second copy
tearing the first one down. `core/00-namespace.js` resolves it by looking at the bundle NAME:

| what it finds | what it does |
|---|---|
| the same build already running | a literal duplicate — returns, does nothing |
| the same bundle name, a different build | an upgrade — stops the old one and takes over |
| a **different** bundle name | **joins**: adopts the running framework and registers only its own modules |

The build wraps `core/10-*`…`core/50-*` in `if (!JFX_JOINED)`, so a joining bundle never re-runs the
core. That guard is load-bearing, not tidiness: without it the joining copy re-assigns `JFX.util`,
`JFX.api` and `JFX.player` on the shared object, handing the already-running modules a brand-new
player instance nobody is subscribed to. The symptom is subtle — every module reports `running: true`
and nothing throws, but one plugin's events silently stop arriving. `tools/coexist-check.mjs` exists
to catch exactly that.

## Writing a module

Drop a file into `addons/mods/`, name it `NN-name.js` (the number is load order), and call
`JFX.register()` exactly once:

```js
JFX.register({
    id:       'myThing',              // also the key in JFX.config
    title:    'Human name',           // used in logs
    defaults: { enabled: true },      // merged into JFX.config.myThing
    css:      '@@css:mods/NN-name.css@@',   // optional, see below
    init:     function (cfg) {},      // once, when the module starts
    route:    function (cfg) {},      // optional, on every hashchange
    tick:     function (cfg) {},      // optional, debounced 150 ms after DOM mutations
    destroy:  function () {}          // optional, when the module is switched off
});
```

* `this` inside every hook is the module object, so state goes on `this`, not in a file-level `var`.
* A hook that throws marks the module broken and stops it; the rest of the bundle carries on. The
  add-on is never allowed to take the page down with it.
* `tick` runs on *every* DOM mutation batch anywhere in the app. Make the "nothing to do" path cheap
  (one `querySelector`) and make the work idempotent — mark what you have already touched, the way
  `rowTags` compares against the existing attribute and `cardMeta` uses `:not([data-jfx-meta])`.
* `'@@css:<path>@@'` is replaced at build time by the contents of that file as a string literal, so a
  module's baseline styles can be authored as real CSS. `JFX.util.injectCss()` puts the sheet in as
  the **first** child of `<head>`, i.e. the weakest sheet on the page — the theme's Custom CSS
  (rendered last, inside the React root) overrides it at equal specificity. Styles that the theme
  owns belong in `src/*.css`; the module ships only the floor that makes it usable on a bare Jellyfin.

### What core gives you

| | |
|---|---|
| `JFX.util` | `t` / `addStrings` (i18n, `%s` placeholders), `log` (only when `config.debug`), `warn`, `el`, `slugify`, `injectCss`, `debounce`, `reducedMotion`, `ticksToMinutes`, `clamp` |
| `JFX.api` | `ctx()` → `{address, token, userId, deviceId}` or `null`, `get(path, params)`, `imageUrl(id, type, tag, maxWidth)`, `getItem(id)` (cached), `nowPlaying()` (this device's session DTO — a guess, see below), `session()`, `command(path, params)` (the one POST — see `episodePicker`), `forget()` |
| `JFX.player` | `on/off(event, fn)` for `attach · detach · play · pause · seeking · seeked · ended · item`, plus `state` (incl. `mode`: `'video'` or `'dom'`), `resolveItem()`, `forget()`, `matchesMedia(item)`, `remaining()`, `surface()` |
| `JFX.home` | `isCurrent()`, `container()` — the *visible* home page, not the `.hide`den leftovers viewManager keeps around |

Every request goes to **the server the user is already logged into**, authenticated with the token
`window.ApiClient` already holds. Everything is a GET except `command()`, which POSTs a
remote-control command to this device's own session so that `episodePicker` can start an episode —
there is no other way in, and it only ever runs on a click. Nothing writes library data or settings.

## Configuration

Three layers, later ones win:

1. the `defaults` of a module, then rebuild;
2. a global defined **before** the bundle runs:
   ```js
   window.JELLYFLIX_ADDON_CONFIG = { cardMeta: { enabled: true }, pauseInfo: { delayMs: 800 } };
   ```
3. from the browser console, persisted in `localStorage` and applied immediately:
   ```js
   JellyFlixAddon.setConfig({ pauseInfo: { showOverview: false } });
   JellyFlixAddon.setConfig({ debug: true });     // turn on JFX.util.log
   JellyFlixAddon.setConfig(null);                // forget the stored overrides
   ```

## The `pauseInfo` module

When playback stays paused for `delayMs`, a Netflix-style block fades in over the left of the frame:
the series logo (for an episode) or the film's logo — falling back to its name as text — then
`S1:E4 · Episode title`, then year / age rating / runtime / genres / time left, then the synopsis. It
goes away the moment playback resumes, and while scrubbing.

| option | default | |
|---|---|---|
| `enabled` | `true` | |
| `delayMs` | `350` | a shorter pause is almost always a seek; a card that blinks on every scrub is worse than no card |
| `dim` | `true` | darken the whole frame, not just the left ramp |
| `showLogo` | `true` | `false` = always use the text title |
| `showOverview` | `true` | |
| `showRemaining` | `true` | "21 min left", from the media element, only above one minute |
| `overviewChars` | `420` | hard cap; CSS also line-clamps |
| `logoMaxWidth` | `600` | px requested from the server |

Two things worth knowing if you touch it:

* **Where the item comes from, and why it is checked.** `playbackManager` lives inside jellyfin-web's
  bundle and is not reachable from a userscript, so `JFX.player` derives everything from the `<video>`
  element. Three sources, in order:
  1. the media URL — direct play puts the item id straight in `/Videos/{id}/stream…`;
  2. the resource-timing log — transcoded HLS hands hls.js an opaque `blob:` URL, but the manifest
     and segment requests it made are still recorded, newest first;
  3. `/Sessions?deviceId=…` — what the server thinks this device is playing.

  **None of the three is trusted on its own.** Each candidate is checked against the media element
  with `matchesMedia()`: `RunTimeTicks` has to be within 5 % (at least 10 s) of `video.duration`. A
  wrong title is wrong by minutes, a right one by well under a second, and the tolerance is loose
  enough that slightly-off metadata never costs a correct card. When the duration is not known yet
  the check cannot judge and passes — `durationchange` re-runs it and re-resolves if it now disagrees.

  This matters most for source 3. Jellyfin keeps **one session row per device** and swaps its
  `NowPlayingItem` when the client reports playback start, so for a second or two after switching
  titles the row still names the previous one. Accepting that first answer is what made the card show
  the film you watched *before*; now a disagreeing session is a reason to wait and ask again (6 tries,
  600 ms apart) rather than to believe it. If nothing ever passes, no card is drawn — showing the
  wrong title is worse than showing none.
* **Where the card is mounted.** Inside `.videoPlayerContainer`, directly after the `<video>`, with
  **no z-index anywhere**. The OSD and the subtitle layers paint above it by DOM order alone; a
  z-index would put the card over the subtitles, and a z-index on `.videoPlayerContainer` itself would
  hide the whole OSD behind the video. (Verified against jellyfin-web 12.1:
  `plugins/htmlVideoPlayer/style.scss` and `apps/legacy/controllers/playback/video/`.)

## The `episodePicker` module

While an episode is playing, a button appears in the OSD control row. It opens a drawer listing the
current season's episodes — thumbnails, runtime, synopsis, how far through each one you already are,
and the one you are watching marked — with a season selector in the header. Picking another episode
starts it.

| option | default | |
|---|---|---|
| `enabled` | `true` | |
| `thumbnails` | `true` | off makes the rows compact and saves an image request per episode |
| `showOverview` | `true` | |
| `overviewChars` | `180` | hard cap; the list also line-clamps |
| `thumbWidth` | `320` | px requested from the server |

* **How playback is started.** `playbackManager` is inside jellyfin-web's bundle and cannot be called
  from an injected script. The way in is the one the Cast button already uses: `POST
  /Sessions/{id}/Playing?playCommand=PlayNow&itemIds=…` addressed to **this device's own session**,
  which the client then acts on via its own websocket. This is the only write the add-on makes
  anywhere, and it only ever happens on a click.
* **Where it mounts.** The button borrows Jellyfin's own `paper-icon-button-light` classes and goes
  into `.videoOsdBottom .buttons`, so it inherits the OSD styling and the auto-hide. The drawer goes
  in as the **last child of `#videoOsdPage`**, which puts it above the control shelf by DOM order
  alone — no z-index — and keeps it on screen when the shelf hides after three seconds. It starts
  below the app bar, because that toolbar is a later sibling and paints over anything the drawer puts
  up there.

## Installing

There is no custom-JS field anywhere in jellyfin-web 12.1 — Custom CSS is the only thing the Dashboard
will take — so the bundle has to reach the page some other way. In order of preference:

### 1. As a Jellyfin plugin (recommended)

`plugins/pause-info-card/` in this repository is a real Jellyfin plugin that carries the bundle. Install it from the
catalogue and every browser that talks to the server gets the add-on, including the ones on TVs, with
a settings page in the Dashboard and nothing to paste anywhere.

1. Dashboard → Plugins → **Repositories** → **+**, URL:
   `https://raw.githubusercontent.com/TerminatorXL/JellyFlix/main/manifest.json`
2. Catalogue → **Pause Info Card** and/or **Episode Picker** → Install → restart the server.
3. Dashboard → Plugins → the plugin's name for its settings.

One repository URL carries both, and they are independent: install either, or both. Each injects its
own script tag and ships the modules it owns; at runtime the second bundle to load joins the first
one's framework rather than replacing it (see [Two plugins, one framework](#two-plugins-one-framework)).

**Requires Jellyfin 12.x** (`targetAbi 12.0.0.0`). Verified on `jellyfin/jellyfin:12.1`.

How it reaches the page:

* `Services/ScriptInjectionStartupFilter` is an `IStartupFilter`, registered by
  `Services/PluginServiceRegistrator` — the one hook a plugin gets into the ASP.NET pipeline. Its
  middleware buffers the response for `/web/`, `/web/index.html` and `/web`, and inserts one
  `<script defer src="../PauseInfoCard/addon.js?v=…">` before `</body>`. Nothing on disk is touched, so a
  server upgrade cannot undo it and the read-only web root in the Docker image is not a problem. The
  `src` is deliberately relative, so an install under a sub-path (`/jellyfin/web/`) resolves correctly.
* `PauseInfoCardController` serves that URL. The bundle is an embedded resource in the DLL, and the
  Dashboard settings are prepended to it as `window.JELLYFLIX_ADDON_CONFIG`, which the registry merges
  over the module defaults. Saving settings changes the served file immediately — no restart.
* The route is `[AllowAnonymous]`, because a `<script src>` cannot send an Authorization header. It
  gives nothing away: the file is the same bundle published here, and it reads the viewer's own
  session at runtime through `window.ApiClient`.

Building it yourself:

```bash
npm run build          # the JS bundle first — it is embedded into the DLL
npm run build:plugin   # compiles in mcr.microsoft.com/dotnet/sdk:10.0, writes the zip + manifest.json
```

Jellyfin 12.1 targets **net10.0**, which is newer than most machines' SDK, so the compile runs in the
official container — the same reason `tools/pw.sh` runs Playwright in one. Nothing but Docker is
needed on the host. The script writes `dist/plugin/<slug>_<version>.zip` and refreshes `manifest.json`
(source URL + MD5) so the repository URL above keeps working straight after a push.

**The repository holds plugins, plural.** A plugin is a directory under `plugins/` with a `plugin.json`
(guid, name, assembly, slug, targetAbi, catalogue text) beside its C# project; `manifest.json` carries
one entry per guid and the build script leaves the others alone. Adding a second plugin is adding a
directory and running `npm run build:plugin -- --plugin <slug>`. The JavaScript under `addons/` stays
the shared framework for all of them, which is why its global is still `JellyFlixAddon` and its
classes are still `.jfx-*`: the repository is JellyFlix, the plugins are named after what they do.

### 2. The "JavaScript Injector" plugin

If you already run n00bcodr's injector, `npm run apply` writes the current build into its config over
the API — no copy-pasting 68 KB of JavaScript:

```bash
JF_URL=https://server JF_TOKEN=xxx npm run apply
```

`--private` puts the entry in `private.js` instead of the public bundle, `--disable` uploads it
switched off, `--remove` deletes it. Saving restarts Jellyfin; other scripts in that plugin are left
alone. Do not run this **and** install the plugin from §1 — the page would load the add-on twice.
(It would survive that: two copies of the same build stand down for each other. But it is pointless.)

### 3. Userscript manager (per client)

Tampermonkey/Violentmonkey install straight from `dist/jellyflix-addon.user.js` — only that one browser
gets it, which makes it the quickest way to try a change without touching the server. The
`@match *://*/web/*` header covers any host.

### 4. Reverse proxy

If nginx already fronts Jellyfin, serve the file and splice a tag in. Needs `sub_filter_types text/html`
and no compression on the upstream:

```nginx
sub_filter '</body>' '<script src="/jellyflix-addon.user.js"></script></body>';
sub_filter_once on;
```

### Not covered

Native apps (Android, Android TV, Kodi, Infuse) do not load jellyfin-web, so the add-on cannot reach
them, whichever route you pick.

**Jellyfin Desktop / Media Player is a special case, twice over.** From **v1.11.0** it loads
jellyfin-web from the server, so the plugin reaches it like any browser. Before v1.11.0 it renders a
copy of jellyfin-web bundled inside the application, which no server-side plugin can touch — the
server's Custom CSS still applies there, because the client fetches that over the API, but an injected
`<script>` tag cannot. The fix is to update the desktop app; there is nothing to do on the server.

Even once the script arrives, that client **plays through libmpv, not through a `<video>` element**:
the OSD is ordinary jellyfin-web markup while the picture is painted by a native layer. `JFX.player`
detects this and switches to its `dom` mode, reading playback state off the OSD instead — see the
header of `addons/core/30-player.js`.

It is also its own browser, with its own HTTP cache: the first launch after installing the plugin has
to revalidate index.html before it sees the tag. Jellyfin serves that document `Cache-Control:
no-cache`, so the revalidation is guaranteed and no cache clearing is needed — but only from plugin
**1.0.3.0** onwards, which is the version that stopped that revalidation coming back as a 304.

### Checking it landed

Hard-refresh and run in the console:

```js
JellyFlixAddon.version                              // "1.0.0"
JellyFlixAddon.modules.map(m => [m.id, m.running])  // four modules, cardMeta false by default
```

## Testing

`tools/addon-check.mjs` is a functional check for `pauseInfo` — it plays an item, pauses it, and
reports what the card actually rendered (logo URL and `naturalWidth`, headline, `S1:E1` line, meta
line, synopsis), shoots it with the OSD both asleep and awake, then resumes and verifies the card
really goes away. By default it runs against a stock Jellyfin, which is how you check that the
module's stylesheet stands on its own; `--css <file>` injects a stylesheet of yours the way Jellyfin
renders Custom CSS.

```bash
tools/pw.sh tools/addon-check.mjs --profiles modern-desktop,modern-mobile,tv
```

`tools/picker-check.mjs` does the same for `episodePicker`: it plays an episode, checks the button
lands in the OSD row, opens the drawer, reads back the seasons and episodes, switches season, then
clicks a different episode and verifies playback actually moved.

`tools/coexist-check.mjs` installs nothing but assumes both plugins are — it loads a page, checks
every module from both bundles is registered and running, and then exercises both features on the
same page. It is the guard on the join mechanism described above.

```bash
tools/pw.sh tools/picker-check.mjs
tools/pw.sh tools/coexist-check.mjs
```

`--server` injects nothing at all, which is how you verify a server-side install: the card has to come
from the plugin (or the proxy) alone. It prints the version the page actually sees:

```bash
tools/pw.sh tools/addon-check.mjs --server --profiles modern-desktop
# [modern-desktop] add-on version seen by the page: 1.0.0
```
